# ExplorerOne

ExplorerOne — небольшое приложение в системном трее Windows, которое объединяет окна Проводника в обычные вкладки Проводника Windows 11. Оно работает без установки и не требует прав администратора.

## Что делает приложение

При запуске ExplorerOne собирает уже открытые окна Проводника в одно главное окно. Новые окна Проводника, в том числе открытые через `Win+E`, ярлык или команду «Показать в папке», также переходят во вкладки этого окна. Дополнительное новое окно быстро сворачивается на время переноса, а главное остаётся активным. Первое и главное окна не сворачиваются.

Исходное окно закрывается только после проверки папки и выделения в целевой вкладке. При ошибке, выходе из утилиты или истечении времени ожидания окно, свёрнутое ExplorerOne, разворачивается обратно. Оно всё время доступно на панели задач. Если целевая вкладка успела создаться до сбоя, она тоже может остаться открытой.

Windows создаёт новое окно раньше, чем COM-интерфейсы позволяют перенести его во вкладку, поэтому короткая вспышка или анимация сворачивания всё ещё возможна. Сворачивание происходит раньше полного завершения переноса; готовность вкладки проверяется отдельно.

ExplorerOne остаётся в области уведомлений. Пункт выхода в меню значка завершает работу приложения. В одном пользовательском сеансе работает один экземпляр ExplorerOne.

Для открытия вкладок приложение использует встроенные возможности Проводника Windows 11 22H2 или новее (сборка 22621+). Пользовательский интерфейс и системный трей собраны для .NET 10; опубликованный архив содержит автономную версию для Windows x64 и не требует установленного .NET Runtime.

## Как устроена интеграция

Компонент на одном потоке STA получает уведомления WinEvent о создании и показе окон; резервный таймер обнаруживает пропущенные события. Очередь обрабатывает готовые окна без отдельной паузы между переносами. Полный список нативных окон доступен даже до готовности их COM-представлений.

Вкладки связываются с COM `ShellWindows` через `IShellBrowser.GetWindow`. Для создания вкладки отправляется внутренний код команды `0xA21B`, который upstream использует для `Ctrl+T`. Это не публичный стабильный API Windows, и обновление системы может изменить его работу. Перед закрытием источника проверяются все вкладки исходного и целевого окон, папка, выделение, HWND и PID. Регистрация постороннего окна не задерживает уже готовую пару. COM-вызовы остаются сериализованными.

## Ограничения

- Если запущена **Explorer Tab Utility (ETU)**, сначала завершите её обычной командой выхода из её меню в системном трее. ExplorerOne откажется запускаться, пока процесс ETU работает; он никогда не завершает этот процесс самостоятельно.
- Перенос окон использует COM-интерфейсы Windows Shell. Ошибки доступа, недоступное сетевое расположение или отказ навигации оставляют исходное окно открытым.
- При неполном или меняющемся снимке исходного или целевого окна перенос этой пары откладывается. После неудачи могут остаться дополнительная пустая вкладка или уже перенесённые копии; исходное окно остаётся доступным. Повтор использует созданные вкладки, пока их состояние не изменено.
- Для временного сворачивания предусмотрен таймер возврата через четыре секунды ожидания. Утилита не скрывает источник; пользователь может развернуть его через панель задач.
- Отдельный синхронный COM-вызов Windows Shell нельзя надёжно прервать таймером. Если Shell зависнет внутри такого вызова, значок в трее тоже может временно перестать отвечать; исходное окно до проверки не закрывается.
- Состояние источника должно совпасть в нескольких последовательных чтениях. Для пустого выделения оставлен больший интервал на позднюю команду «Показать в папке». Выделение повторно проверяется перед закрытием. Необычно поздние команды сторонних программ и изменения окон в самый момент переноса нельзя атомарно согласовать через API Проводника.
- Для системных или повышенных окон, окон другого пользователя и окон на других виртуальных рабочих столах поведение зависит от ограничений Windows Shell и сеанса пользователя. ExplorerOne не повышает свои права и не обходит эти ограничения.
- Автозапуск выключен по умолчанию. При включении ExplorerOne создаёт только собственное значение в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`; отключение удаляет только это значение. Изменение не требует прав администратора.
- Перед включением автозапуска выберите постоянную папку для программы. Меню отражает наличие её записи Run; отдельно отключённый в диспетчере задач автозапуск нужно разрешить там же.
- ExplorerOne не сохраняет историю и состояние окон, не восстанавливает сеансы, не ищет открытые вкладки и не перехватывает клавиатуру или мышь. WinEvent используется только для уведомлений об окнах. В приложении нет глобальных горячих клавиш и режима обхода объединения.

## Запуск и сборка из исходников

Для разработки нужен .NET 10 SDK. Приложение не использует сторонние NuGet-пакеты.

```powershell
dotnet run --project src/ExplorerOne -c Release
```

Сборка приложения:

```powershell
dotnet build src/ExplorerOne/ExplorerOne.csproj -c Release
```

Консольный набор тестов запускается так:

```powershell
dotnet run --project tests/ExplorerOne.Tests -c Release
```

Чтобы собрать автономную версию для Windows x64:

```powershell
dotnet publish src/ExplorerOne/ExplorerOne.csproj -c Release -r win-x64 --self-contained true -o publish/ExplorerOne-win-x64
Copy-Item LICENSE, THIRD-PARTY-NOTICES.md, README.md -Destination publish/ExplorerOne-win-x64/
Copy-Item docs/manual-tests.md -Destination publish/ExplorerOne-win-x64/
Copy-Item docs/verification.md -Destination publish/ExplorerOne-win-x64/
```

## Установка из архива

Распакуйте `ExplorerOne-win-x64.zip` в удобную папку и запустите `ExplorerOne.exe`. Это переносимая сборка: установщик не нужен. Чтобы удалить приложение, завершите его через меню значка в трее и удалите распакованную папку. Если автозапуск был включён, сначала выключите его в меню ExplorerOne.

Перед первым запуском вручную завершите ETU, если она установлена и запущена. Не завершайте её принудительно через диспетчер задач.

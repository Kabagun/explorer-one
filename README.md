# ExplorerOne

ExplorerOne открывает новые папки во вкладках одного Проводника Windows 11. Приложение работает в системном трее и устанавливается для текущего пользователя без прав администратора.

## Открытие папок

В поддерживаемой версии Проводника ExplorerOne получает системный запрос до создания отдельного окна и передаёт адрес папки напрямую новой нативной вкладке существующего окна. В этом пути нет `Ctrl+T`, промежуточной «Главной» и последующей навигации из пустой вкладки. Содержимое папки загружает сам Проводник; скорость зависит также от диска, сети и расширений Shell.

Команда «Показать в папке» использует ответ нового представления Проводника, чтобы Windows могла выделить нужный файл. Если подходящего главного окна нет, Windows создаёт первое окно обычным способом.

При запуске ExplorerOne также собирает уже существующие окна в главное. Для запросов, которые создают отдельный процесс Проводника, предусмотрен резервный путь: исходное окно временно скрывается, а вкладка создаётся напрямую с адресом папки. При неизвестном профиле Проводника используется прежний перенос с промежуточной вкладкой.

Пункт **«Открывать папки сразу во вкладках»** в меню значка включает прямой маршрут. Настройка сохраняется для текущего пользователя; ассоциации папок Windows не заменяются. Выход из ExplorerOne отключает перехват. После перезапуска Проводника приложение подключается к новой оболочке; этот сценарий проверен с сохранением открытых папок и выделения.

## Совместимость и ограничения

- Windows 11 22H2 или новее, x64. Прямой маршрут включается только для проверенных профилей `ExplorerFrame.dll`: **10.0.26100.8972** (SHA-256 `b7bda6011c0c13a81a6ea9670789c3ecb241caf994d31e274add18704929ca6d`) и **10.0.26100.9949** (`07fb43dee1863a28bfd6f69cb503fceae735570ec55955124c5b330061b16933`). При неизвестном профиле используется резервный перенос.
- Обновление Windows может потребовать нового профиля совместимости. ExplorerOne не применяет неизвестные смещения и не меняет системные файлы.
- Сначала завершите **Explorer Tab Utility**, если она запущена. ExplorerOne обнаруживает конфликт и просит закрыть ETU; самостоятельно её не завершает.
- Системные окна, повышенные процессы, другие пользователи и другие виртуальные рабочие столы могут ограничивать работу Shell-интерфейсов. Приложение не повышает права.
- В резервном переносе одного окна источник может закрыться до завершения загрузки целевой вкладки. При ошибке приложение показывает предупреждение. Для много-вкладочных окон состояние назначения проверяется перед закрытием источника.
- Файлы не изменяются. История папок и восстановление сеанса не сохраняются.

## Установка и автозапуск

Скачайте и откройте `ExplorerOne-Setup-1.0.0-win-x64.exe` из [релизов GitHub](https://github.com/Kabagun/explorer-one/releases/latest). Мастер установит приложение, добавит ярлык в меню «Пуск» и предложит автозапуск. Если на компьютере нужна среда .NET Desktop Runtime 10, установщик автоматически загрузит её с сайта Microsoft. Для этого потребуется интернет.

В меню значка включите **«Запускать при входе в Windows»**. ExplorerOne создаёт задачу `ExplorerOne-<SID текущего пользователя>` в Планировщике заданий Windows. Она запускает приложение в интерактивном сеансе текущего пользователя через 20 секунд после входа, без повышения прав и без ограничения длительности работы. При ошибке запуска выполняются до трёх повторов с интервалом в минуту — например, если диск с приложением ещё недоступен. После запуска задержка открытия папок не добавляется.

Для обновления запустите новый установщик. Если открыта переносная версия 0.2.x, сначала завершите её через **«Выход»** в трее. Для переезда с переносной версии оставьте автозапуск включённым в мастере, чтобы задача указывала на установленный ExplorerOne.

Удаление доступно в **«Параметры → Приложения → Установленные приложения»**. Деинсталлятор завершит ExplorerOne и снимет автозапуск. Журналы и пользовательские настройки хранятся отдельно.

## Журнал диагностики

Журналы находятся в `%LOCALAPPDATA%\ExplorerOne\Logs`. Пункт **«Открыть папку журналов»** в меню значка открывает эту папку. Она создаётся автоматически; если запись недоступна, приложение продолжает работать без журнала.

В JSONL записываются запуск и версия, готовность приложения, запрос штатного выхода, завершение Windows-сеанса, необработанные ошибки и состояние нативного маршрута. Раз в 30 секунд сохраняются отметка активности и последняя стадия работы. Повторяющиеся одинаковые ошибки ограничены одной записью за 30 секунд.

Для исключений сохраняются тип, HRESULT и названия методов стека. Текст исключения, содержимое файлов, пути открытых папок, имена пользовательских файлов и командная строка в журнал не попадают. Журналы локальные, автоматической отправки нет. Хранятся не более десяти JSONL-файлов размером до 1 МиБ каждый, отдельно — небольшое состояние сеанса.

Если предыдущий процесс завершился без отметки штатного выхода, следующий запуск добавляет `session_interrupted`. Принудительное завершение, потеря питания или фатальная нативная ошибка могут не дать обработчику записать причину: в таком случае останутся последняя отметка активности и признак незавершённого сеанса. Это не следует автоматически считать доказательством конкретной ошибки или блокировки.

## Сборка

Нужны .NET 10 SDK, PowerShell 7, Visual C++ Build Tools x64 и Windows SDK. Для установщика нужен [Inno Setup](https://jrsoftware.org/inno-setup). Скрипт сборки использует установленные инструменты. Интерфейс и очередь запросов написаны на C#, нативный маршрут — на C++. MinHook 1.3.4 включён в исходники с лицензией. Сторонних NuGet-пакетов нет.

```powershell
dotnet run --project tests/ExplorerOne.Tests -c Release
dotnet run --project tests/ExplorerOne.Startup.Tests -c Release
./tests/ExplorerOne.Native.Tests/run.ps1
dotnet build ExplorerOne.sln -c Release
dotnet publish src/ExplorerOne/ExplorerOne.csproj -c Release -r win-x64 --self-contained false -o publish/ExplorerOne-win-x64
Copy-Item LICENSE, THIRD-PARTY-NOTICES.md, README.md -Destination publish/ExplorerOne-win-x64/
New-Item -ItemType Directory -Path publish/ExplorerOne-win-x64/docs -Force | Out-Null
Copy-Item docs/manual-tests.md, docs/verification.md -Destination publish/ExplorerOne-win-x64/docs/
./installer/build.ps1 -PublishedDirectory publish/ExplorerOne-win-x64 -OutputDirectory outputs
```

Нативная DLL получает имя по хешу исходников, а `ExplorerOne.NativeLaunchRouter.current` указывает нужный файл. Это позволяет обновлять приложение, пока прежний процесс Проводника ещё держит предыдущий модуль.

Для скрытого резервного переноса используются системные хуки создания и показа окон. Windows может загрузить DLL и в другие графические процессы; обработчики сначала проверяют, что работают внутри системного `explorer.exe`, и только затем обращаются к его окнам. Перехват ввода не используется.

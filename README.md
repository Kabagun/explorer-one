# ExplorerOne

ExplorerOne открывает новые папки во вкладках одного Проводника Windows 11. Приложение работает в системном трее, без установщика и прав администратора.

## Открытие папок

В поддерживаемой версии Проводника ExplorerOne получает системный запрос до создания отдельного окна и передаёт адрес папки напрямую новой нативной вкладке существующего окна. В этом пути нет `Ctrl+T`, промежуточной «Главной» и последующей навигации из пустой вкладки. Содержимое папки загружает сам Проводник; скорость зависит также от диска, сети и расширений Shell.

Команда «Показать в папке» использует ответ нового представления Проводника, чтобы Windows могла выделить нужный файл. Если подходящего главного окна нет, Windows создаёт первое окно обычным способом.

При запуске ExplorerOne также собирает уже существующие окна в главное. Для запросов, которые создают отдельный процесс Проводника, предусмотрен резервный путь: исходное окно временно скрывается, а вкладка создаётся напрямую с адресом папки. При неизвестном профиле Проводника используется прежний перенос с промежуточной вкладкой.

Пункт **«Открывать папки сразу во вкладках»** в меню значка включает прямой маршрут. Настройка сохраняется для текущего пользователя; ассоциации папок Windows не заменяются. Выход из ExplorerOne отключает перехват. После перезапуска Проводника приложение подключается к новой оболочке; этот сценарий проверен с сохранением открытых папок и выделения.

## Совместимость и ограничения

- Windows 11 22H2 или новее, x64. Прямой маршрут включается только для проверенного профиля `ExplorerFrame.dll` **10.0.26100.8972**, SHA-256 `b7bda6011c0c13a81a6ea9670789c3ecb241caf994d31e274add18704929ca6d`. При неизвестном профиле используется резервный перенос.
- Обновление Windows может потребовать нового профиля совместимости. ExplorerOne не применяет неизвестные смещения и не меняет системные файлы.
- Сначала завершите **Explorer Tab Utility**, если она запущена. ExplorerOne обнаруживает конфликт и просит закрыть ETU; самостоятельно её не завершает.
- Системные окна, повышенные процессы, другие пользователи и другие виртуальные рабочие столы могут ограничивать работу Shell-интерфейсов. Приложение не повышает права.
- В резервном переносе одного окна источник может закрыться до завершения загрузки целевой вкладки. При ошибке приложение показывает предупреждение. Для много-вкладочных окон состояние назначения проверяется перед закрытием источника.
- Файлы не изменяются. История папок и восстановление сеанса не сохраняются.

## Установка и автозапуск

Распакуйте автономный архив `ExplorerOne-win-x64.zip` в постоянную папку и запустите `ExplorerOne.exe`. Установленный .NET Runtime не требуется.

В меню значка включите **«Запускать при входе в Windows»**. ExplorerOne создаёт собственную запись в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. Если запуск отдельно запрещён в диспетчере задач, разрешите его там.

Для удаления выключите автозапуск, завершите приложение через меню значка и удалите распакованную папку. Загруженный нативный модуль освобождается при следующем перезапуске Проводника; после выхода он не перенаправляет запросы.

## Сборка

Нужны .NET 10 SDK, PowerShell 7, Visual C++ Build Tools x64 и Windows SDK. Сборка сама находит существующий MSVC; инструменты не устанавливаются автоматически. Интерфейс и очередь запросов написаны на C#, нативный маршрут — на C++. MinHook 1.3.4 включён в исходники с лицензией; сторонних NuGet-пакетов нет.

```powershell
dotnet run --project tests/ExplorerOne.Tests -c Release
./tests/ExplorerOne.Native.Tests/run.ps1
dotnet build ExplorerOne.sln -c Release
dotnet publish src/ExplorerOne/ExplorerOne.csproj -c Release -r win-x64 --self-contained true -o publish/ExplorerOne-win-x64
Copy-Item LICENSE, THIRD-PARTY-NOTICES.md, README.md -Destination publish/ExplorerOne-win-x64/
New-Item -ItemType Directory -Path publish/ExplorerOne-win-x64/docs -Force | Out-Null
Copy-Item docs/manual-tests.md, docs/verification.md -Destination publish/ExplorerOne-win-x64/docs/
```

Нативная DLL получает имя по хешу исходников, а `ExplorerOne.NativeLaunchRouter.current` указывает нужный файл. Это позволяет обновлять приложение, пока прежний процесс Проводника ещё держит предыдущий модуль.

Для скрытого резервного переноса используются системные хуки создания и показа окон. Windows может загрузить DLL и в другие графические процессы; обработчики сначала проверяют, что работают внутри системного `explorer.exe`, и только затем обращаются к его окнам. Перехват ввода не используется.

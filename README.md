# ExplorerOne

ExplorerOne — небольшое приложение в системном трее Windows, которое объединяет окна Проводника в обычные вкладки Проводника Windows 11. Оно работает без установки и не требует прав администратора.

## Что делает приложение

При запуске ExplorerOne собирает уже открытые окна Проводника в одно главное окно. Новые окна Проводника, в том числе открытые через `Win+E`, ярлык или команду «Показать в папке», также переходят во вкладки этого окна.

Для обычного нового видимого окна Проводника ExplorerOne ставит в очередь Windows команду `Ctrl+T` (`PostMessage`) при событии создания/показа, если уже известно подходящее главное окно. Native worker делает это до alpha-подавления окна и чтения его COM-состояния, не ожидая COM и не вызывая `SetForegroundWindow` перед командой. Общая резервация сопоставляет команду с точным новым HWND; обработчик принимает именно эту вкладку без повторного `Ctrl+T`. После согласованного снимка папки и выделения приложение запрашивает закрытие источника, а навигация и выделение в целевой вкладке завершаются в фоне. Закрытие источника и готовность папки — отдельные этапы; перенос не ждёт завершения фоновой загрузки. Windows должна сначала создать исходное окно, поэтому ExplorerOne не может поставить команду в очередь раньше этого момента. Поздняя команда «Показать в папке» может изменить выделение после снимка и потому не попасть в новую вкладку — это ограничение похоже на поведение ETU.

Если пользователь успел изменить предварительно открытую вкладку, ExplorerOne сохраняет это расположение и сообщает о незавершённом переносе, не перезаписывая вкладку. Если фоновая навигация или перенос выделения завершается ошибкой после закрытия источника, приложение показывает предупреждение в трее с просьбой открыть папку снова. Файлы приложение не изменяет, историю и восстановление сеанса не ведёт. Для окон с несколькими вкладками и сохранённого резервного переноса действует режим сначала копирования: целевое состояние проверяется до закрытия источника, а при ошибке источник остаётся доступным.

Для временного подавления дополнительного окна native worker задаёт ему layered alpha 0 при создании/показе. Предварительно открывать вкладку он пытается только для нового видимого обычного окна; скрытые и свёрнутые окна не получают скрытую standby-вкладку. Окно остаётся настоящим HWND Проводника: это не перенаправление `ShellExecute` и не гарантия отсутствия вспышки на пикселях. ExplorerOne не сворачивает окно в основном пути; сворачивание используется только при невозможности alpha-подавления. Пока запрошенное фоновое закрытие не удалило исходный HWND, alpha 0 удерживается. Первое главное окно и уже существовавшие при запуске окна, включая свёрнутые, не меняются. Исходный вид живых окон восстанавливается при ошибке, потере главного окна, тайм-ауте в четыре секунды или обычном завершении работы.

Alpha-состояние и жизнь HWND — разные наблюдения; наличие HWND само по себе не означает видимый кадр. Приложение не измеряет экранные пиксели и не обещает, что вспышка исключена.

ExplorerOne остаётся в области уведомлений. Пункт выхода в меню значка завершает работу приложения. В одном пользовательском сеансе работает один экземпляр ExplorerOne.

Для открытия вкладок приложение использует встроенные возможности Проводника Windows 11 22H2 или новее (сборка 22621+). Пользовательский интерфейс и системный трей собраны для .NET 10; опубликованный архив содержит автономную версию для Windows x64 и не требует установленного .NET Runtime.

## Как устроена интеграция

Для поиска уже известного главного окна сначала проверяется ранее найденная вкладка, чтобы не обращаться первой к новой загружающейся «Главной». Сохраняются только индекс регистрации и идентификаторы окна/вкладки; расположение, тип представления и COM-связь проверяются заново. Совпадающие файловый путь и его URL после однократного декодирования сравниваются без повторного разбора через Shell. Эти оптимизации сокращают проверки, но не превращают перенос в прямую обработку запроса открытия: Windows сначала создаёт источник, затем вкладка отдельно загружает папку.

Через connection point `ShellWindows.WindowRegistered` поток-владелец COM получает дополнительный сигнал пробуждения очереди. Отдельный native worker получает WinEvent о создании окна и напрямую отслеживает его показ, активацию и завершение сворачивания, даже пока COM-вызов занят. Резервный таймер обнаруживает пропущенные события. Очередь COM работает на своём STA и принимает следующие окна, не дожидаясь загрузки уже открываемых вкладок. Полный список нативных окон доступен даже до готовности их COM-представлений.

Вкладки связываются с COM `ShellWindows` через `IShellBrowser.GetWindow`. Для создания вкладки отправляется внутренний код команды `0xA21B`, который upstream использует для `Ctrl+T`. Это не публичный стабильный API Windows, и обновление системы может изменить его работу. Новый быстрый перенос сохраняет снимок одной вкладки в памяти до завершения фоновой операции. Для много-вкладочного окна и резервного переноса перед закрытием проверяются все вкладки обоих окон, папка, выделение, HWND и PID. COM-вызовы выполняются на одном STA-потоке; во время асинхронных ожиданий очередь может обработать следующее окно.

Во время волны `ShellWindows.WindowRegistered` ExplorerOne снимает полный нативный список окон, а затем ищет вкладки через COM в области свежепроверенного главного окна. Это не глобальный COM-перечень на каждый сигнал; если главное окно неизвестно, используется полный резервный путь. Уже принадлежащий фоновой операции источник повторно через COM не обнаруживается. Исходные полные проверки перед закрытием много-вкладочного окна и резервного переноса сохраняются. Согласованный снимок файлового URL разрешается при `Busy` только после двух одинаковых наблюдений документа и выделения; пространства имён проходят строгую проверку по умолчанию. При свободном Shell стартовая проверка существующих окон только читает состояние.

Создание вкладки и подавление видимости дополнительного окна — независимые этапы. Alpha-подавление не означает, что вкладка создаётся мгновенно.

## Ограничения

- Если запущена **Explorer Tab Utility (ETU)**, сначала завершите её обычной командой выхода из её меню в системном трее. ExplorerOne откажется запускаться, пока процесс ETU работает; он никогда не завершает этот процесс самостоятельно.
- Перенос окон использует COM-интерфейсы Windows Shell. В быстром переносе одного окна источник закрывается до завершения фоновой навигации; при её ошибке приложение просит открыть расположение снова. В режиме сначала копирования для много-вкладочных окон и резервного переноса ошибки оставляют источник доступным.
- В режиме сначала копирования при неполном или меняющемся снимке исходного или целевого окна перенос этой пары откладывается. После неудачи могут остаться дополнительная пустая вкладка или уже перенесённые копии; источник остаётся доступным. Повтор использует созданные вкладки, пока их состояние не изменено.
- При сбое фоновой операции уже созданная вкладка может остаться пустой. ExplorerOne закрывает только точную зарезервированную вкладку, если она всё ещё активна, показывает «Главная», не имеет выделения и её состояние не изменилось при проверке до и после. Изменённую, не «Главная», неактивную или неоднозначную вкладку приложение сохраняет; произвольные вкладки оно не закрывает.
- При выходе приложение прекращает новые предварительные открытия и ожидает выполнения уже отправленных запросов не дольше шести секунд; закрывать неподтверждённую или произвольно выбранную вкладку оно не пытается.
- Дополнительное окно может оставаться настоящим HWND с alpha 0, пока идёт быстрый перенос и подтверждается его закрытие. Если alpha-подавление недоступно или не срабатывает, используется резервное сворачивание; при ошибке, потере главного окна, тайм-ауте через четыре секунды и обычном выходе исходный вид живых окон восстанавливается. По существованию HWND нельзя судить о том, был ли он виден на экране.
- Отдельный синхронный COM-вызов Windows Shell нельзя надёжно прервать таймером. Если Shell зависнет внутри такого вызова, значок в трее тоже может временно перестать отвечать.
- В быстром режиме расположение и выделение источника снимаются один раз; очень поздняя команда «Показать в папке» может прийти после этого снимка. В режиме сначала копирования состояние источника проверяется в нескольких последовательных чтениях; для пустого выделения оставлен больший интервал на такую команду, а выделение проверяется перед закрытием. Изменения окон в самый момент переноса нельзя атомарно согласовать через API Проводника.
- Для системных или повышенных окон, окон другого пользователя и окон на других виртуальных рабочих столах поведение зависит от ограничений Windows Shell и сеанса пользователя. ExplorerOne не повышает свои права и не обходит эти ограничения.
- Автозапуск выключен по умолчанию. При включении ExplorerOne создаёт только собственное значение в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`; отключение удаляет только это значение. Изменение не требует прав администратора.
- Перед включением автозапуска выберите постоянную папку для программы. Меню отражает наличие её записи Run; отдельно отключённый в диспетчере задач автозапуск нужно разрешить там же.
- ExplorerOne не сохраняет историю и состояние окон, не восстанавливает сеансы, не ищет открытые вкладки и не перехватывает клавиатуру или мышь. WinEvent используется только для уведомлений об окнах. В приложении нет глобальных горячих клавиш и режима обхода объединения.

## Запуск и сборка из исходников

Для разработки нужен .NET 10 SDK. Приложение не использует сторонние NuGet-пакеты.

```powershell
dotnet run --project src/ExplorerOne -c Release
```

Сборка приложения:

```powershell
dotnet build src/ExplorerOne/ExplorerOne.csproj -c Release
```

Консольный набор тестов запускается так:

```powershell
dotnet run --project tests/ExplorerOne.Tests -c Release
```

Чтобы собрать автономную версию для Windows x64:

```powershell
dotnet publish src/ExplorerOne/ExplorerOne.csproj -c Release -r win-x64 --self-contained true -o publish/ExplorerOne-win-x64
Copy-Item LICENSE, THIRD-PARTY-NOTICES.md, README.md -Destination publish/ExplorerOne-win-x64/
New-Item -ItemType Directory -Path publish/ExplorerOne-win-x64/docs -Force | Out-Null
Copy-Item docs/manual-tests.md, docs/verification.md -Destination publish/ExplorerOne-win-x64/docs/
```

## Установка из архива

Распакуйте `ExplorerOne-win-x64.zip` в удобную папку и запустите `ExplorerOne.exe`. Это переносимая сборка: установщик не нужен. Чтобы удалить приложение, завершите его через меню значка в трее и удалите распакованную папку. Если автозапуск был включён, сначала выключите его в меню ExplorerOne.

Перед первым запуском вручную завершите ETU, если она установлена и запущена. Не завершайте её принудительно через диспетчер задач.
